# STRADA

공개 사이트: https://strada-film-discovery.vercel.app

영화에서 다음 영화로 이어지는 디깅 서비스입니다. 검색·포스터·한국어 제목·줄거리는 TMDB의 실제 메타데이터를 사용합니다. 추천은 GPT가 읽을 수 있는 비평, 영화제 프로그램과 학술 자료를 참고해 생성합니다. 가입 없이 브라우저에 경로를 저장하며, 문헌 DB는 서버의 읽기 전용 검색 사본으로 연결합니다.

## 실행

Node.js 22와 npm을 사용합니다.

```sh
npm ci
cp .env.example .env.local
npm run dev
```

`.env.local`의 `OPENAI_API_KEY`, `TMDB_READ_ACCESS_TOKEN`을 채웁니다. 서버 주소는 http://127.0.0.1:5173 입니다.

## GitHub + Vercel 배포

GitHub 비공개 저장소: https://github.com/swjeon0/strada-film-discovery

Vercel의 STRADA 팀에서 이 저장소를 연결합니다. Framework는 Next.js, 프로젝트 루트는 저장소 루트입니다. `main` 브랜치 변경을 Production에 자동 배포합니다. `npm run build`는 동일한 표준 Next.js 배포 빌드입니다.

Production과 Preview 환경변수에는 다음 값을 등록합니다. API 키에는 `NEXT_PUBLIC_` 접두사를 붙이지 않습니다.

- `OPENAI_API_KEY`
- 추천 목록의 메인 판단은 현재 `gpt-5.6-terra`, reasoning `none`을 한 번 호출합니다. 모델 실험은 `npm run benchmark:curator-v1`에서 별도로 합니다.
- `TMDB_READ_ACCESS_TOKEN`

앱과 모든 영화 API는 Vercel의 Node.js 서버에서 실행됩니다. 앱 자체의 일일·사용자별 AI 탐색 횟수 제한과 동시 요청 개수 제한은 없습니다. 추천·재생성·상세 설명은 이전 사용 횟수와 관계없이 실행하며, Cloudflare 비용 카운터를 호출하지 않습니다. 기존 `PUBLIC_MODE`, `QUOTA_SERVICE_URL`, `QUOTA_SERVICE_SECRET` 설정이 남아 있어도 사용하지 않습니다. `infra/quota`는 예전 배포의 보관용 코드이며 현재 Vercel 앱의 의존성이 아닙니다.

요청당 시간·출력 길이·검색 범위 제한, 같은 요청 공유, 캐시는 유지합니다. OpenAI 계정 자체의 잔액과 공급자 요청 제한은 그대로 적용됩니다. 비용 값은 API 사용량 기반 추정치이며 중단된 호출에서 사용량을 받지 못하면 실제 청구가 더 클 수 있습니다.

`.env.local`, `.vercel`, 인증 파일, 개발 로그는 GitHub에 올리지 않습니다. 저장소와 ZIP에도 비밀 키를 포함하지 않습니다.

## 추천 동작

추천은 선택한 모든 영화를 같은 비중의 한 집합으로 읽고 `gpt-5.6-terra`를 한 번 호출해 하나의 12편 프로그램을 만듭니다. 큐레이터는 미학적 논제에 답하도록 강제되지 않습니다. 직접적인 사실 관계부터 작품의 형식, 역사, 인물, 장소를 잇는 복잡한 해석까지, 실제로 탐색 가치가 가장 높은 관계를 자유롭게 고릅니다. 연결의 종류나 복잡성 자체에는 가산점을 주지 않습니다. 문헌 DB는 원문 위치와 관찰을 제공하며 후보 영화를 제한하지 않습니다. DB에 없는 실제 영화도 제안할 수 있습니다.

모델 출력은 정확히 12편뿐이며 예비 후보나 숨은 대체 목록이 없습니다. 로컬 catalogue와 TMDB가 제목·원제·대체 제목·연도·감독을 확인하고, 일반 제목 검색이 약한 작품은 해당 감독의 TMDB 연출 필모그래피에서 다시 확인합니다. 식별에 실패한 슬롯이 있으면 `gpt-5.4`가 그 자리만 한 번 다시 고르고 12편 전체를 재검증합니다. 추천 순위를 두 번 만드는 구조가 아니라 잘못된 작품 정체성만 복구하는 예외 경로입니다. UI에는 검증된 12편만 전달합니다.

모든 시작·따라가기·직접 추가 영화는 순서와 관계없이 같은 비중입니다. 개별 추천이 한 갈래를 깊게 파는 것은 허용하지만 12편 전체는 선택작 모두를 의미 있게 다뤄야 합니다. 과거에 표시만 된 영화는 취향으로 간주하지 않습니다. 정렬은 모델의 큐레이션 판단을 따르며, 코드가 중복과 새 영화 조건을 강제합니다.

‘다른 영화 찾기’는 현재 경로에서 이전에 표시된 모든 추천을 제외하고 같은 선택으로 새 12편을 생성합니다. 따라가기와 직접 추가도 현재 경로에 없는 영화로 새 프로그램을 만듭니다. 성공한 요청만 스냅샷으로 저장하며, 재생성은 경로에 영화 한 편을 추가한 것으로 계산하지 않습니다. Undo, 경로 기록, 브라우저 이동은 저장된 정확한 스냅샷을 복원합니다. 되돌린 뒤 다른 길로 이어가도 버려진 분기에서 표시한 영화 ID는 제외 기록에 남습니다. 최근 최대64개 스냅샷을 저장하고, 오래된 스냅샷을 줄여도 제외할 영화 ID는 보존합니다(최대5000개). 새 경로를 시작하면 이 제외 기록을 초기화합니다.

현재 온라인 경로는 정규화 SQLite 문헌 DB에서 빌드한 읽기 전용 검색 사본을 사용합니다. 영화 식별자·제목/별칭, 키워드, 미리 계산한 문헌 의미 이웃을 한 번에 조회합니다. 단문 발췌와 별도로 작성한 관찰·적용 한계를 함께 모델에 전달합니다. 원문을 확인한 AI 검토와 사람 검수를 구분하며 현재 문헌은 agent_reviewed입니다. 초록만 있는 학술논문은 수집기와 온라인 경로 양쪽에서 제외합니다. 자료가 없는 영화도 모델의 열린 큐레이션으로 진행합니다. 자세한 구조와 추가 방법은 [문헌 DB 안내](research/knowledge/README.md)에 있습니다.

비평은 모델이 실제로 읽은 출처의 맥락입니다. 추천 영화와의 비교는 STRADA의 해석이며, 비평가가 그 비교를 직접 했다는 뜻이 아닙니다. 출처가 없으면 AI 해석으로 표시하고 가짜 인용은 만들지 않습니다.

## 실패 복구와 이미지

추천 API의 전체 목표는 20초입니다. 그 안에서 입력 메타데이터 조회, 로컬 문헌 조회, 메인 큐레이터 호출, 12편의 TMDB 식별과 필요한 경우의 슬롯 복구를 끝냅니다. 메인 호출 한도는 15.75초, 복구 호출 한도는 3.75초이고 Vercel 함수 한도는 30초입니다. 처음에는 현재 언어의 짧은 설명만 생성합니다. 포스터를 열면 서명된 연결 정보로 긴 설명을 별도 생성합니다.

구조화 출력이 잘리거나 12편 중 하나라도 식별되지 않으면 부분 목록으로 낮추지 않고 실행을 실패로 기록합니다. 상세 설명 실패는 추천 목록에 영향을 주지 않습니다. 조회 결과와 상세 설명 캐시는 서버 인스턴스 수명에 한정되며 영구 저장소를 가정하지 않습니다.

검색에서 고른 포스터는 선택 후 상세 정보 조회, 추천 생성, 새로고침에도 유지합니다. 이미지가 실제로 로딩되지 않을 때는 검증된 상세 정보의 대체 포스터를 사용합니다.

## 문헌 추가와 테스트 기록

```sh
npm run knowledge:build
npm run knowledge:embed -- --run
npm run knowledge:audit
npm run knowledge:test
```

`records/*.json`에 본문을 읽고 위치를 확인한 자료를 추가하고, DB 빌드와 변경된 관찰 임베딩을 갱신한 뒤 함께 배포합니다. 원문 전문은 공개 번들에 넣지 않습니다. 현재 원본 DB는 로컬 SQLite이고 Vercel에는 검증된 JSON 검색 사본을 배포합니다. 원격 PostgreSQL은 아직 만들지 않았으며 이전용 migration과 저장소 경계만 준비돼 있습니다.

결과의 **탐색 기록**에서 전체 요청 시간·단계별 시간·직접 문헌이 있는 선택작 수·자료 버전을 확인하고 추천 JSON을 저장할 수 있습니다. 시간은 API 응답 수신까지이며 포스터 다운로드를 제외합니다. 이 기록은 브라우저에만 저장합니다.

## 확인

```sh
npm test

```

새 배포 주소는 기존 Cloudflare 주소와 다른 출처이므로 브라우저 저장 공간도 분리됩니다. 기존 경로는 원래 주소의 브라우저 저장소에 남아 있습니다.
