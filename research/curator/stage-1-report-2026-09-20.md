# STRADA 고맥락 큐레이터 1단계 최종 보고서

> 역사 기록: 이 문서는 초기 10초·`gpt-5.4-mini`·reserve 실험의 결론을 보존한다. 현재 운영 구조는 20초·`gpt-5.6-terra`·정확히 12편의 단일 출력으로 바뀌었으며, 최신 판단은 `stage-1.5-quality-pilot-2026-09-20.md`를 따른다.

## 최종 판정

**1단계는 완료했고, 2단계로 넘어가도 된다.**

이 판정의 범위는 “한 번의 고맥락 판단 호출로 실제 영화 12편을 약 10초 안에 만들 수 있는가”이다. 최종 고정 시험 24회 중 23회가 성공했고, 성공 실행은 모두 10초 안에 끝났다. 성공률과 전체 시도 대비 10초 통과율은 95.8%, 성공 실행 p50은 6.214초, p95는 6.646초였다. 남은 한 번의 실패는 9.5초 provider timeout이며, 잘못된 JSON·중복·영화 식별 실패는 최종 시험에서 0건이었다.

따라서 온라인 추론 구조를 다시 늘릴 이유는 없다. 지금 드러난 핵심 한계는 작은 문헌 snapshot의 편향과 coverage 부족이다. 이것은 2단계의 문헌 저장소와 정규화된 영화 ID가 해결해야 하는 문제다.

이 판정은 “이미 인간 큐레이터 수준이다”라는 뜻이 아니다. 전문가 블라인드 평가와 학습 데이터 구축은 이후 평가 단계의 일이다.

## 최종 구조

1. 선택작 1–8편을 순서와 최근성 가중치 없이 한 집합으로 받는다.
2. 저장소에서 선택작 직접 passage를 우선 확보하되, 주변 비평 문맥도 포함해 최대 24개 passage를 만든다.
3. `gpt-5.4-mini`, reasoning `none`을 한 번만 호출한다.
4. 모델은 12개 주 후보와 12개 압축 reserve를 반환한다. 주 후보만 짧은 연결축과 provenance를 갖고, reserve는 제목·연도·감독만 갖는다.
5. 로컬 catalogue와 TMDB가 이름 순서, 악센트, 1–2년의 개봉연도 차이, 대체 제목을 정규화한다.
6. 입력작과 중복을 제거한 뒤 앞에서부터 실제 영화 12편을 확정한다. 부족하면 명시적으로 실패한다.
7. reserve가 최종 12편에 들어오면 상세 설명은 기존 상세 단계에서 필요할 때 생성한다. 추천 판단 LLM 호출은 추가되지 않는다.

출력 계약은 모든 추천에 모든 선택작 ID를 anchor로 넣는다. `source_explicit`는 한 passage가 선택작과 추천작을 실제로 함께 다룰 때만 유지한다. 문헌이 개념을 제공하고 모델이 연결을 만든 경우는 `source_supported_interpretation`, 문헌 근거가 없는 경우는 `model_proposal`이다. 모델 제안에는 evidence ID를 붙이지 않는다.

한국어 요청인데 모델이 영어 lens를 반환한 2/23건은 첫 세 개의 한국어 연결축으로 lens를 결정론적으로 재구성하도록 보완했다. 번역을 위한 추가 호출은 없다.

## 고정 자료와 평가 입력

| 항목 | 수량 | 내용 |
|---|---:|---|
| 확인된 passage | 17 | 비평 10, 프로그램 노트 3, 영화제 2, 학술 2 |
| 고정 입력 조합 | 12 | 단일 1개, 2편 조합 10개, 3편 조합 1개 |
| 최종 반복 | 조합당 2회 | 총 24회, 실패도 그대로 포함 |
| 운영 추천 경로 변경 | 0 | 독립 실험과 평가 장치만 구현 |

12개 입력에는 자료가 있는 작품과 거의 없는 작품을 함께 넣었다. 예: *Close-Up*, *Ten Skies + Young Mr. Lincoln*, *Chunhyang + Boyhood*, *Boyhood + The Bridges of Madison County*, *Close-Up + F for Fake*, *Koyaanisqatsi + Ten Skies*, *Sans Soleil + Paris, Texas*.

## 최종 측정

| 지표 | 결과 |
|---|---:|
| 성공 | 23 / 24 (95.8%) |
| 전체 시도 중 10초 이내 성공 | 23 / 24 (95.8%) |
| 성공 실행 총시간 p50 / p95 / max | 6.214초 / 6.646초 / 6.694초 |
| 모델 시간 p50 / p95 | 5.761초 / 6.284초 |
| 영화 식별 시간 p50 / p95 | 0.420초 / 0.563초 |
| 출력 토큰 p50 / p95 | 794 / 844 |
| 최종 시험 추정 비용 | $0.09728 / 24회 |
| 구조·식별 실패 | 0 |
| provider timeout | 1 |

비용은 provider usage와 프로젝트 단가표로 계산한 추정값이며 청구서 금액은 아니다.

초기 14후보 계약은 24회 중 13회만 성공했다(54.2%). 이름 순서와 개봉연도 정규화, 정확 제목의 연도 없는 재검색, 더 많은 reserve를 더한 중간 계약은 각각 75.0%, 83.3%를 기록했다. 최종적으로 reserve의 설명과 provenance를 제거해 출력 길이를 줄이자 95.8%와 p95 6.646초에 도달했다. 이 과정에서 큐레이션 판단 호출은 계속 한 번이었다.

모델 비교에서는 `gpt-5.6-luna`가 9.5초 제한을 넘겼고, `gpt-5.6-terra`는 한 케이스를 9.246초에 완성했지만 12편에 같은 연결 문구를 반복했다. `gpt-5.4-mini`가 속도, 짧은 연결축의 구체성, 비용의 균형이 가장 나아 최종 설정으로 선택됐다. Sol은 사용하지 않았고 코드에서도 차단했다.

## 품질 감사

두 번 모두 성공한 11개 조합에서 같은 영화가 다시 나온 비율은 평균 29.5%였다. 조합별 공통 추천은 2–5편이었다. 재실행이 거의 같은 목록을 반복하지 않으면서도 완전히 무작위로 흩어지지는 않았다.

reserve는 성공 실행 23회 중 11회에서 사용됐고, 전체 276개 최종 추천 중 20개(7.2%)였다. 즉 식별 안정성을 높이되 대부분의 추천은 짧은 연결축과 provenance를 가진 주 후보에서 나왔다.

반면 작은 snapshot의 편향은 분명하다.

- 성공 실행 23회 중 11회는 선택작 가운데 적어도 한 편에 직접 passage가 0개였다.
- `News from Home`은 20/23회, `Jeanne Dielman`은 17/23회 등장했다. 이는 선택작과 무관한 보편적 정답이라기보다 현재 snapshot이 아커만 자료를 과대표집한 결과다.
- 최종 276편 중 `source_supported_interpretation`은 80편, `model_proposal`은 196편, `source_explicit`는 0편이었다. 직접 비교 문헌이 거의 없는 작은 corpus에서 직접 근거를 꾸며내지 않은 것은 맞지만, DB가 아직 고맥락 추천의 우위를 만들 만큼 촘촘하지 않다는 뜻이기도 하다.
- 같은 작품이 로컬 ID와 TMDB ID로 나뉘는 사례가 실행 간에 있었다. 한 실행 안의 중복은 제거됐지만, 2단계에는 영구 canonical film ID와 외부 ID 매핑이 필요하다.

추천 자체의 정성 표본은 가능성을 보였다. *Koyaanisqatsi + Ten Skies*에서는 *La Région Centrale*, *Wavelength*, *News from Home*, *Dream of Light*, *The Four Times*가 나와 지속, 비인간적 리듬, 풍경과 시선의 형식을 잇는 경로를 만들었다. 그러나 coverage가 빈 입력에서는 *Jeanne Dielman*, *Tokyo Story*, *Sans Soleil* 같은 안전한 정전 작품으로 회귀하는 경향이 강했다. 이것이 2단계의 우선 문제다.

## 2단계 진입 판단

2단계로 넘어갈 조건은 충족했다.

- 한 번의 LLM 호출만으로 12편을 확정할 수 있다.
- 10초 목표는 성공 실행 p95 6.646초로 여유 있게 통과했다.
- 영화 식별 실패는 reserve와 정규화로 제거했다.
- 실패가 숨겨지지 않고 timeout으로 계측된다.
- 남은 가장 큰 오차가 추론 단계 수가 아니라 corpus coverage와 canonical identity라는 사실이 측정으로 확인됐다.

2단계에서는 현재 17개 fixture를 무작정 늘리는 대신 다음 순서로 진행해야 한다.

1. 영구 `film`, `work_alias`, `document`, `passage`, `mention`, `relation` ID를 확정한다.
2. 현재 과대표집된 감독·작품과 coverage 0 입력을 기준으로 수집 우선순위를 만든다.
3. passage마다 원문 위치, 권리 상태, 직접 언급 영화, 관계 종류, 추출 신뢰도, 인간 검토 상태를 저장한다.
4. 온라인 호출의 17개 고정 snapshot을 선택작별 quota가 있는 검색 결과로 교체하되, 후보 영화 목록은 여전히 DB에 가두지 않는다.
5. 이 12개 고정 케이스와 동일한 측정 계약으로 회귀 시험한다. 10초와 성공률을 유지하면서 아커만 편향, coverage 0, `model_proposal` 비중이 줄어드는지를 본다.

현재 `curator_v1`을 곧바로 운영 추천 API에 연결하지는 않는다. 2단계 저장소가 생기기 전 연결하면 작은 snapshot의 편향을 제품 행동으로 굳히기 때문이다.

## 재현 명령

```bash
npm run benchmark:curator-v1 -- --case matter-and-sky
npm run benchmark:curator-v1 -- --run --case all --models gpt-5.4-mini --repeat 2 --reasoning none --deadline-ms 9500 --max-output-tokens 1100 --out work/curator-v1-stage1-acceptance.json
```

이번 최종 원본은 로컬 `work/curator-v1-stage1-final-acceptance.json`에 있다. API 키와 authorization header는 기록하지 않는다.
