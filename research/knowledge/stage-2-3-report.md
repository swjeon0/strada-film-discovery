## 데이터 구조와 확장 방식

`문헌 → 변경 불가능한 문헌 버전 → 발췌 / 비평적 관찰 → 참여 영화 / 증거 연결` 구조다. 비교, 대조, 영향, 개별 작품 분석, 역사적 맥락, 공동 상영을 구분한다. 같은 프로그램에 여러 작품이 있으면 하나의 다자 관계로 보존하며, 모든 영화쌍을 자동으로 관련 있다고 만들지 않는다.

각 관찰에는 원문 위치, 작성자·발행처·날짜·URL, 영어/한국어 요약, 그 자료가 입증하지 않는 범위, 영화 식별자, 접근 범위와 사용 조건을 보존한다. 짧은 원문은 대조 가능한 위치 표지다. 그 짧은 문장만으로 글 전체의 요약이 입증된다고 표시하지 않는다. 자동 정리는 `agent_reviewed`이며 사람 검토와 구분된다.

원본 입력은 `records/*.json`, 작업 DB는 `work/knowledge/corpus.sqlite`, 온라인 자료는 `serving-index.json`과 `semantic-neighbors.json`이다. SQLite DB에는 버전·체크포인트·격리된 오류·검토 기록·관찰 임베딩을 실제 저장한다. 배포 서버는 작은 읽기 전용 자료를 메모리에 올린다. 별도의 유료 DB 서비스를 요구하지 않는다. PostgreSQL/pgvector 스키마는 준비했지만 원격 DB를 설치한 것은 아니다.

문헌 수정은 새 버전으로 추가되며 영화의 영속 ID는 유지한다. 같은 입력 재실행은 중복 문헌·벡터를 생성하지 않는다. 잘못된 참조·애매한 영화 합치기·초록 논문은 격리한다. 삭제된 문헌의 과거 버전은 감사 기록으로만 남고 서비스로 보내지 않는다. 임베딩은 `text-embedding-3-small`, 256차원이며 바뀐 관찰만 오프라인에서 계산한다.

현재 인덱스는 작은 파일럿에 맞는 메모리 기반 구현이다. 자료가 커지면 번들 크기·콜드 스타트·검색 지연을 측정하여 동일 ID와 테이블을 PostgreSQL 검색 어댑터로 이전해야 한다. 대규모 서비스가 검증된 것으로 간주하지 않는다. 2,000개 합성 문헌 검사에서 재시작·중복 방지·구조적 확장을 점검했지만 웹 수집이나 해석 품질의 확장성을 증명하는 검사는 아니다.

## 온라인 추천

1. 선택 영화의 TMDB 메타데이터를 읽는다. 모든 선택작은 동일 비중이며 경로 순서로 가중하지 않는다.
2. 영화 식별·단어 검색·미리 계산한 의미 이웃으로 문헌 관찰을 찾는다. DB에 없는 영화는 줄거리 단어로 관련 맥락을 찾을 수 있으며, 자료가 없어도 추천 입력으로 허용한다. 최대 16개 관찰, 직렬화된 본문 15KB까지만 LLM에 전달한다. 문헌 수가 많은 한 작품이 문맥을 독점하지 않게 선택작별 자료를 먼저 고려한다.
3. `gpt-5.6-terra`가 전체 선택과 관찰을 읽어 정확히 12편의 큐레이션을 한 번에 구성한다. 장르·국가·관계 유형별 강제 할당은 없다. DB 영화만 고르게 하지도 않는다.
4. TMDB에서 제목·연도·감독·중복·제외 목록을 병렬 검증한다. 식별에 실패한 자리만 `gpt-5.4`로 한 번 교체하고 다시 검증한다. 성공 응답은 항상 검증된 서로 다른 12편이다. 공급자 장애 때 12편 미만을 성공처럼 보여 주지 않으며 이전 경로를 보존한다.
5. 포스터를 누르면 `gpt-5.4-mini`가 설명을 확장한다. 이것은 목록 응답을 지연시키지 않는다. 문헌의 원래 관찰과 모델이 만든 작품 간 연결을 별도로 표시한다.

Sol은 사용하지 않는다. 목록 전체 서버 예산은 20초, 클라이언트 통신 대기 한도는 25초다. 외부 API·네트워크 장애 때문에 모든 요청이 반드시 20초 내 성공한다는 보장은 없다.

재생성은 지금까지 노출한 영화를 제외하고, Follow/수동 추가는 직전 12편을 모두 제외한다. 단순히 노출된 영화는 선호 신호로 가중하지 않는다.

## 직접 테스트와 자료 확대

결과 화면의 **탐색 기록**에서 시간·모델·전달/사용 문헌 수·선택작 직접 자료 범위를 보고 추천 JSON을 저장할 수 있다. 영화 상세의 출처 카드에는 원문 위치·요약·해석 범위를 표시한다. 이전 문헌 버전으로 만든 경로에는 과거 기록임을 알린다.

다음 확대는 특정 영화의 개수를 채우는 방식보다 현재 빠진 시대·지역·영화 전통과 유용한 비교/대조를 포함하는 문헌으로 진행한다. 문헌당 여러 관찰을 추가할 수 있으나 저작권·발췌 한도와 맥락의 정확성을 유지해야 한다.

```sh
python3 scripts/build-knowledge.py --audit
npm run knowledge:embed -- --run
npm run knowledge:audit
npm run knowledge:test
npm test
npm run typecheck
npm run build
node --import tsx scripts/smoke-curator-production.ts --run --workflow --detail
```

`knowledge:embed -- --run`과 `smoke-curator-production --run`은 유료 모델 호출을 포함할 수 있다. 감사 명령은 외부 문헌을 가져온다. 실제 CLI 플래그는 각 스크립트와 `README.md`를 따른다. 원문 전체와 키는 Git에 올리지 않는다.

사람 평가에는 ‘정답 영화’ 일치율을 사용하지 않는다. 같은 입력을 같은 모델의 문헌 없는 큐레이션과 무작위 A/B로 비교하고, 선택의 설득력·구체성·발견 가치·목록 완성도·사실 오류·자료 활용을 평가한다. 현재는 평가 저장 테이블과 실행 도구만 준비되어 있으며, 사람 평가 결과나 추가학습 성능은 아직 없다.
